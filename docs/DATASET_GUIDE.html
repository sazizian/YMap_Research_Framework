Y-Map dataset and execution guide

Run commands from the YMap_Research_Framework folder. The canonical collection is Dataset/; .Dataset is accepted by the dataset tools as an alias, not a second stored copy. This guide covers the current Y-Map tools. Preserved upstream instructions remain with their original records.

1. Install the current package

Extract the archive to a short local destination such as C:\YMap. The preserved historical collection includes long relative paths, so use this short destination instead of a deeply nested OneDrive or Downloads folder. Open PowerShell in the extracted project folder. Confirm that Python is at least version 3.10 and that the project file exists:

python --version
Test-Path .\pyproject.toml
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m ymap_research doctor

Test-Path should return True. If Windows has py but not python, create the environment with py -3 -m venv .venv, then use the same .venv executable above. Activation is optional. On Linux/macOS, replace .\.venv\Scripts\python.exe with .venv/bin/python.

3. Build and inspect the catalog

.\.venv\Scripts\python.exe -m ymap_research dataset index --root .
.\.venv\Scripts\python.exe -m ymap_research dataset summary --root .
.\.venv\Scripts\python.exe -m ymap_research dataset list --root . --source ymap --limit 10 --offset 0
.\.venv\Scripts\python.exe -m ymap_research dataset list --root . --source ymap --system customer_order --kind sql --limit 10

The source filters distinguish ymap, reinforceorm and ymap_legacy. System and kind filters let you narrow a large listing. --limit and --offset page through records without opening the entire collection. Use --help to inspect all options and supported kind names:

The source field identifies the artifact collection, rather than the algorithm that produced every schema. Historical exhaustive solutions and comparator outputs are part of the ReinforceORM archive too. origin_method uses an explicit tool folder when available; otherwise it records mixed_or_unspecified_in_source.

.\.venv\Scripts\python.exe -m ymap_research dataset list --help
.\.venv\Scripts\python.exe -m ymap_research dataset show --help
.\.venv\Scripts\python.exe -m ymap_research dataset export --help

Copy an entry ID from a listing, then replace ENTRY_ID_FROM_LIST in this command:

.\.venv\Scripts\python.exe -m ymap_research dataset show --root . --id ENTRY_ID_FROM_LIST

For a SQL entry, add --out runs/selected_schema.sql to save its exact bytes to a new file. Existing destination files are not overwritten.

CSV files and Excel workbooks can be read as rows as well. List entries with --kind table or --kind workbook, copy the selected ID, and run:

.\.venv\Scripts\python.exe -m ymap_research dataset table --root . --id ENTRY_ID_FROM_LIST --limit 20

For an Excel workbook, add --sheet "Sheet name" when needed. Values retain their source units and CSV identifiers remain text. Excel formulas are returned as stored formula text rather than executed.

To export a small SQL subset as candidate records for inspection:

.\.venv\Scripts\python.exe -m ymap_research dataset export --root . --source ymap --limit 10 --out runs/exported_subset

The export creates candidates.jsonl, parse_rejections.csv and export_manifest.json. It parses supported physical SQL structure and creates no measurement labels. Exported features are projected into a common physical view. This is separate from the generator's full logical mapping metadata; for profiling use the original Dataset/YMap/Generated/candidates.jsonl or a fresh generate output. --limit 10 examines at most ten SQL occurrences; unsupported entries are recorded as rejections, so fewer candidates may be exported. Keep original IDs and source paths with every subset. Do not infer an exact schema match from a similar model name alone.

The combined catalog contains 80,248 SQL occurrences and 38,606 distinct SQL byte sequences. These include imported files and copies under different paths, including earlier archives; they are not 80,248 current Y-Map candidates. Equal SHA-256 values identify equal bytes, not semantic equivalence. The generation manifest's 728 candidates and a catalog's SQL-file count therefore answer different questions.

4. Run the packaged overview and reanalysis

.\.venv\Scripts\python.exe Minimal_Example_CLI_Tool/run_ymap.py --root .
.\.venv\Scripts\python.exe reproduction/run_ymap.py --root .

The minimal entry point reads source records and refreshes their catalog without changing imported files. The reproduction runner indexes and verifies the collection and runs the historical-record analysis in a new timestamped directory under results/YMap/reproduction_runs/. Neither command executes imported SQL, trains the paper's model or performs new database measurements.

The timestamped reproduction runner above is the recommended repeatable entry point. To run the analysis directly, choose a fresh output folder:

.\.venv\Scripts\python.exe -m ymap_research dataset analyze --root . --out results/YMap/analysis_run_01

Use a new name for every run, for example analysis_run_02 next time. The release already contains results/YMap/historical_analysis/; the analysis command preserves existing outputs and refuses to overwrite that folder. Its default destination is therefore unsuitable for rerunning analysis in this shipped release.

The shipped historical analysis, and each fresh analysis output folder, include:

File under results/YMap/historical_analysis/ Purpose
report.md Readable source, scope and results summary
summary.json Counts, provenance, processing boundaries and unresolved protocol details
raw_objective_records.csv Preserved source cost records with derived analysis fields
per_system_pareto_counts.csv Nondominance calculations within each source system
duplicate_id_conflicts.csv Repeated solution IDs with differing records
schema_join_audit.csv Recorded relationships between raw IDs and supplied SQL files
rocket_audit.json Separate comparison of supplied Rocket Controller labels and recomputed nondominance

Original cost strings and records remain unchanged. Historical query/insert/storage units and protocol details that have not been established are recorded as unconfirmed; they must not silently become milliseconds, MB or current PostgreSQL measurements. Repeated records are not automatically averaged, discarded or treated as independent schemas. The report identifies exact analysis boundaries and any unresolved joins.

Supplied ReinforceORM tables remain historical reported outputs. Y-Map values in paperreportedvalues.csv are separately labelled paper transcriptions. A new calculation from historical records is a reanalysis; it is not a new measurement run or automatic confirmation of every table in either paper.

Optional figures

Plots are included under figures/YMap/. To regenerate them from the shipped inputs:

.\.venv\Scripts\python.exe -m pip install -e ".[plots]"
.\.venv\Scripts\python.exe reproduction/build_ymap_figures.py --root .

The outputs include generated-schema counts, historical-record counts and paper_reported_hypervolume, with PNG/SVG versions and figure_sources.json. The hypervolume plot explicitly transcribes the paper's Table 6; its bars are not newly measured benchmark results.

5. Verify preserved files

.\.venv\Scripts\python.exe -m ymap_research dataset verify --root .
.\.venv\Scripts\python.exe -m ymap_research dataset verify --root . --full

The verification report states which catalog/import records were checked. A full check covers the larger preserved collection and can take longer. File verification checks preservation and consistency; it does not authenticate the original measurement procedure or reproduce research conclusions. provenance/imported_archive_manifest.json records the supplied ZIP identity, original member names and relocated paths.

6. Generate a fresh candidate set

The release already includes the 728 current candidates. To run generation again, choose a fresh output folder:

.\.venv\Scripts\python.exe -m ymap_research generate --models Dataset/YMap/Object_Models --out runs/new_candidates --backend python

The Python backend enumerates supported decisions and applies structural checks. For actual Alloy solving, install a JDK, supply an existing local Alloy JAR and select it explicitly:

java -version
javac -version
.\.venv\Scripts\python.exe -m ymap_research generate --models Dataset/YMap/Object_Models/customer_order.json --out runs/new_alloy_candidates --backend alloy --alloy-jar "C:/tools/alloy.jar"

Read SUPPORTEDMAPPINGSEMANTICS.md. Solver satisfaction is bounded by the encoding and supported choices; it is not an unconditional theorem for arbitrary object models. If using --max-candidates, report that it retains an ordered prefix rather than a representative random sample.

7. Collect and evaluate new measurements

Install the driver and configure a dedicated research database:

.\.venv\Scripts\python.exe -m pip install -e ".[postgres]"
$env:YMAP_POSTGRES_DSN = "host=localhost port=5432 dbname=ymap user=ymap password=YOUR_LOCAL_PASSWORD"
.\.venv\Scripts\python.exe -m ymap_research profile --candidates runs/new_candidates/candidates.jsonl --config config/profile.yaml --out runs/new_measurements

Replace the connection details with your own. The optional supplied Compose configuration exposes PostgreSQL on 55432, not 5432. Keep credentials local and use a fresh output folder. The sample profiling configuration is a small new protocol; set the intended distributions, sizes and repetitions before research use. See PROFILING_PROTOCOL.md for units and boundaries.

A measurement CSV requires:

schema_id,object_model,insert_ms,query_ms,storage_mb,label_source,workload_id,environment_id,seed

The IDs must match the exact measured candidate. postgresql_measured identifies executions by this profiler; imported_measured requires actual imported measurement evidence and its source protocol. Changing a label does not change how a record was produced. Do not automatically convert historical units or use formula-generated upstream records as new measured targets.

Evaluate one workload/environment scenario at a time:

.\.venv\Scripts\python.exe -m ymap_research validate --candidates runs/new_candidates/candidates.jsonl --measurements runs/new_measurements/measurements.csv
.\.venv\Scripts\python.exe -m ymap_research evaluate --candidates runs/new_candidates/candidates.jsonl --measurements runs/new_measurements/measurements.csv --config config/evaluation.yaml --out results/YMap/new_evaluation

The calibrated evaluation needs at least three source systems; this is an implementation minimum, not adequate statistical power by itself. Test systems remain held out from fitting and selection normalization. Seeds and repetitions do not create extra independent systems. The structural baselines and optional neural model are separate configurations.

8. Train a deployment model after evaluation

.\.venv\Scripts\python.exe -m ymap_research train --candidates runs/new_candidates/candidates.jsonl --measurements runs/new_measurements/measurements.csv --config config/train.yaml --out runs/final_model.joblib

The recommendation input must contain one source object model. Generate a new one-system file, then recommend from it:

.\.venv\Scripts\python.exe -m ymap_research generate --models Dataset/YMap/Object_Models/customer_order.json --out runs/recommendation_candidates --backend python
.\.venv\Scripts\python.exe -m ymap_research recommend --candidates runs/recommendation_candidates/candidates.jsonl --model runs/final_model.joblib --out results/YMap/customer_recommendations --selection pareto

Recommendation reads schemas and a fitted model, not measurement labels. Final fitting on all supplied data does not replace held-out evaluation. Load only model artifacts that you created or trust.

For the actual optional multi-view neural route, install .[neural], supply authorized local checkpoints and follow NEURAL_BACKEND.md with config/neural.yaml. Tiny local checkpoint tests establish software behavior, not pretrained quality or paper accuracy. Production pretrained weights are not bundled.

9. Preserve attribution and execution boundaries

The original ReinforceORM modules and scripts remain under their original attribution. The upstream minimal CLI is under Minimal_Example_CLI_Tool/Imported_ReinforceORM/; its educational algorithms and supplied reconstructed exports are separate from current Y-Map research computations. Keep imported records unchanged and write derived results to new named output directories.

See LICENSE.md, STATUS.md, VALIDATION_STATUS.json and validation/ for license scopes and exact checks performed. Record the source version, input hashes, configurations, raw measurements, model checkpoints and predictions for each new experiment. Keep corpus construction, per-new-model generation, fitting, prediction and selection costs separate when reporting runtime.
