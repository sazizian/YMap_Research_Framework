# Y-Map Research Framework

This combined research package keeps the supplied ReinforceORM collection, the earlier Y-Map implementation and the current Y-Map code together. It provides a searchable dataset catalog, exact generated SQL candidates, historical-data summaries, and commands for collecting and evaluating new measurements.

Start with [DATASET_GUIDE.md](docs/DATASET_GUIDE.md). All new instructions and entry points are in English.

## Start on Windows

Extract the archive to a short local path such as `C:\YMap`, then open PowerShell in the extracted project folder and check that `pyproject.toml` is present. Preserved historical files have long relative paths; using this short destination avoids adding a long OneDrive or Downloads prefix. Python 3.10 or newer is required.

```powershell
python --version
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m ymap_research doctor
.\.venv\Scripts\python.exe -m ymap_research dataset index --root .
.\.venv\Scripts\python.exe -m ymap_research dataset summary --root .
.\.venv\Scripts\python.exe reproduction/run_ymap.py --root .
```

These commands use the environment's Python directly, so PowerShell activation is unnecessary. On Linux or macOS, use `.venv/bin/python` instead. Run commands from the project root. A smaller entry point prints the collection overview:

```powershell
.\.venv\Scripts\python.exe Minimal_Example_CLI_Tool/run_ymap.py --root .
```

The reproduction runner indexes and verifies files and analyzes supplied records. It does not train a model, profile a database or certify the paper's results.

## Directory map

| Directory | Contents |
|---|---|
| `Dataset/` | Supplied ReinforceORM study data, plus the new `YMap/` collection |
| `Dataset/YMap/Object_Models/` | Current Y-Map JSON object-model inputs |
| `Dataset/YMap/All_SQL_Solutions/<system>/SQL_Solutions/` | Exact SQL files generated by the current Y-Map implementation |
| `ReinforceORM_Old_Artifacts_Initial_Submission/` | Preserved historical collection, including its original data and names |
| `results/` | Supplied ReinforceORM tables; new Y-Map outputs are under `results/YMap/` |
| `reproduction/` | Preserved upstream scripts and the new `run_ymap.py` runner |
| `components/reinforceorm/` | Preserved upstream ReinforceORM modules |
| `Minimal_Example_CLI_Tool/` | New Y-Map overview entry point and preserved upstream files under `Imported_ReinforceORM/` |
| `src/ymap_research/` | Current Y-Map generation, profiling, prediction, recommendation and dataset code |
| `legacy/` | Original earlier Y-Map archive and its provenance |
| `provenance/` | Import manifest and original ReinforceORM root documentation |

`Dataset` is the canonical folder name. The dataset CLI accepts `.Dataset` as an alias for it; this does not create a second copy of the collection.

## Data origins and result interpretation

The import manifest records **110,865 supplied files** and their archive paths. Original root documentation, license and paper copy are retained under `provenance/Imported_ReinforceORM_Root/`. Imported file names, data and attribution remain intact; excluded platform metadata is documented in the manifest.

Current Y-Map object models generate **728 candidate schemas** in this release. Their SQL files are actual generator outputs. Candidate generation alone does not provide latency, storage measurements or trained predictions. Historical summaries preserve source cost values and identity; unestablished units remain unconfirmed. Imported ReinforceORM result tables remain attributed to ReinforceORM.

The combined catalog contains **80,248 SQL file occurrences** and **38,606 distinct SQL byte sequences**, including imported duplicates and earlier archives. These catalog counts do not describe 80,248 newly generated Y-Map schemas.

Y-Map paper-reported values are recorded in [paper_reported_values.csv](results/YMap/paper_reported_values.csv), separately from executed analysis. Transcribing a reported number, exporting a supplied table or checking a file differs from recomputing that number from raw study measurements and the corresponding model. The package preserves these distinctions in its provenance and status records.

Some upstream educational and reconstruction scripts compute objectives from formulas or export paper constants. Their original source and records are preserved. Their outputs are not automatically admitted as newly measured Y-Map labels, and the current Y-Map research pipeline uses its own implementations.

## Figures

The included plots under `figures/YMap/` show current generation counts, historical-record analysis and explicitly sourced paper-reported values. To rebuild them:

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[plots]"
.\.venv\Scripts\python.exe reproduction/build_ymap_figures.py --root .
```

`paper_reported_hypervolume` transcribes manuscript Table 6; it is not a newly executed benchmark. `figures/YMap/figure_sources.json` identifies each input source.

## Run a new measured study

For actual PostgreSQL profiling, install the optional driver and set `YMAP_POSTGRES_DSN` locally. Use a dedicated research database and keep credentials out of the archive.

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[postgres]"
$env:YMAP_POSTGRES_DSN = "host=localhost port=5432 dbname=ymap user=ymap password=YOUR_LOCAL_PASSWORD"
.\.venv\Scripts\python.exe -m ymap_research generate --models Dataset/YMap/Object_Models --out runs/new_candidates --backend python
.\.venv\Scripts\python.exe -m ymap_research profile --candidates runs/new_candidates/candidates.jsonl --config config/profile.yaml --out runs/new_measurements
.\.venv\Scripts\python.exe -m ymap_research validate --candidates runs/new_candidates/candidates.jsonl --measurements runs/new_measurements/measurements.csv
.\.venv\Scripts\python.exe -m ymap_research evaluate --candidates runs/new_candidates/candidates.jsonl --measurements runs/new_measurements/measurements.csv --config config/evaluation.yaml --out results/YMap/new_evaluation
```

`config/profile.yaml` is a small new measurement protocol, not a reconstruction of the original study environment. Use new output folders for each experiment. The Python generator applies supported structural checks; actual Alloy execution requires `--backend alloy`, an Alloy JAR and a JDK. Neural evaluation separately requires PyTorch, Transformers and authorized local pretrained checkpoints. See [PROFILING_PROTOCOL.md](docs/PROFILING_PROTOCOL.md), [SUPPORTED_MAPPING_SEMANTICS.md](docs/SUPPORTED_MAPPING_SEMANTICS.md) and [NEURAL_BACKEND.md](docs/NEURAL_BACKEND.md).

## Verification and attribution

```powershell
.\.venv\Scripts\python.exe -m ymap_research dataset verify --root .
.\.venv\Scripts\python.exe scripts/check_framework.py
```

Read [STATUS.md](STATUS.md) and `VALIDATION_STATUS.json` for the exact software checks and remaining limits. Earlier integration evidence includes Alloy finite-choice solving, PGlite SQL mapping/integrity checks and neural loading/training/save-load with tiny local checkpoints. These checks do not establish new paper results or production pretrained-model accuracy.

The original archive's badge document describes ReinforceORM badge applications. It does not award a badge to this combined Y-Map package. [LICENSE.md](LICENSE.md) explains imported license scopes and attribution. Keep training-corpus construction, per-new-model generation, fitting, prediction and selection costs separate when comparing research methods.
